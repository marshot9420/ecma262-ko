<span id="sec-ecmascript-overview"></span>

다음은 ECMAScript에 대한 비형식적인 개요다. 여기에서는 언어의 모든 부분을 설명하지 않는다. 이 개요는 표준 본문 자체의 일부가 아니다.

ECMAScript는 객체 기반 언어다. 언어의 기본 기능과 호스트 기능은 객체를 통해 제공되며, ECMAScript 프로그램은 서로 통신하는 객체들의 집합이다. ECMAScript에서 객체는 0개 이상의 속성으로 이루어진 컬렉션이며, 각 속성에는 그 속성을 어떻게 사용할 수 있는지를 결정하는 특성이 있다. 예를 들어 어떤 속성의 `Writable` 특성이 `false`로 설정되어 있으면, 실행 중인 ECMAScript 코드가 그 속성에 다른 값을 할당하려는 모든 시도는 실패한다. 속성은 다른 객체, 원시 값 또는 함수를 담는 컨테이너다. 원시 값은 `Undefined`, `Null`, `Boolean`, `Number`, `BigInt`, `String`, `Symbol` 중 하나의 내장 타입에 속한다. 객체는 내장 타입 `Object`에 속하며, 함수는 호출 가능한 객체다. 속성을 통해 객체와 연관된 함수를 메서드라고 한다.

ECMAScript는 ECMAScript 구성 요소의 정의를 완성하는 내장 객체들의 집합도 정의한다. 이러한 내장 객체에는 [전역 객체](doc:value-properties-of-the-global-object#sec-value-properties-of-the-global-object), 그리고 언어의 [런타임 의미론](doc:algorithm-conventions#sec-runtime-semantics)에 핵심적인 `Object`, `Function`, `Boolean`, `Symbol` 및 여러 `Error` 객체가 포함된다. 또한 수치 값을 나타내고 조작하는 `Math`, `Number`, `Date`, 텍스트를 처리하는 `String`과 `RegExp`, 값의 인덱스 기반 컬렉션인 `Array`와 각 요소가 특정한 수치 데이터 표현을 사용하는 서로 다른 아홉 종류의 TypedArray, 키 기반 컬렉션인 `Map`과 `Set`, 구조화된 데이터를 지원하는 `JSON`, `ArrayBuffer`, `SharedArrayBuffer`, `DataView`, 제어 추상화를 지원하는 제너레이터 함수와 `Promise`, 그리고 리플렉션을 지원하는 `Proxy`와 `Reflect`가 포함된다.

ECMAScript는 내장 연산자의 집합도 정의한다. ECMAScript 연산자에는 다양한 단항 연산, 곱셈 연산자, 덧셈 연산자, 비트 시프트 연산자, 관계 연산자, 동등성 연산자, 이항 비트 연산자, 이항 논리 연산자, 할당 연산자 및 쉼표 연산자가 포함된다.

대규모 ECMAScript 프로그램은 모듈을 통해 지원된다. 모듈을 사용하면 프로그램을 여러 개의 문과 선언의 나열로 나눌 수 있다. 각 모듈은 자신이 사용하며 다른 모듈에서 제공되어야 하는 선언과, 자신의 선언 중 다른 모듈에서 사용할 수 있는 선언을 명시적으로 식별한다.

ECMAScript 구문은 의도적으로 Java 구문과 비슷하게 설계되었다. 그러나 사용하기 쉬운 스크립팅 언어로 활용할 수 있도록 ECMAScript 구문에는 완화된 부분이 있다. 예를 들어 변수의 타입을 선언할 필요가 없고, 속성에도 타입이 결부되지 않으며, 정의된 함수의 선언이 그 함수의 호출보다 소스 텍스트상 앞에 나타날 필요도 없다.

<h2 id="sec-objects">
  4.3.1 객체
</h2>

<!-- 원문 제목: Objects -->

<!-- 원문: https://tc39.es/ecma262/multipage/overview.html#sec-objects -->

ECMAScript에는 클래스 정의를 위한 구문이 포함되어 있지만, ECMAScript 객체는 C++, Smalltalk 또는 Java의 객체처럼 근본적으로 클래스에 기반하지 않는다. 대신 객체는 리터럴 표기법이나 생성자 등 다양한 방법으로 생성할 수 있다. 생성자는 객체를 생성한 다음, 그 객체의 속성 전체 또는 일부에 초깃값을 할당하는 코드를 실행하여 객체를 초기화한다. 각 생성자는 프로토타입 기반 상속과 공유 속성을 구현하는 데 사용되는 `"prototype"`이라는 이름의 속성을 가진 함수다. 객체는 `new` 표현식에서 생성자를 사용하여 생성한다. 예를 들어 `new Date(2009, 11)`은 새로운 `Date` 객체를 생성한다. `new`를 사용하지 않고 생성자를 호출했을 때의 결과는 생성자에 따라 달라진다. 예를 들어 `Date()`는 객체가 아니라 현재 날짜와 시간을 나타내는 문자열을 생성한다.

생성자로 생성된 모든 객체는 해당 생성자의 `"prototype"` 속성값을 가리키는 암묵적 참조를 가진다. 이 참조를 객체의 프로토타입이라고 한다. 또한 프로토타입 역시 자신의 프로토타입을 가리키는 `null`이 아닌 암묵적 참조를 가질 수 있으며, 이러한 관계가 계속 이어질 수 있다. 이를 프로토타입 체인이라고 한다. 객체의 속성을 참조하면 프로토타입 체인에서 해당 이름의 속성을 가진 첫 번째 객체의 속성이 참조된다. 다시 말해 먼저 직접 지정된 객체에 해당 속성이 있는지 검사한다. 그 객체에 해당 이름의 속성이 있으면 그 속성이 참조 대상이 된다. 해당 속성이 없으면 그다음으로 그 객체의 프로토타입을 검사하며, 같은 과정이 계속 이어진다.

**그림 1: 객체/프로토타입 관계**

![생성자 CF와 CFp 프로토타입 및 cf1부터 cf5까지의 객체 사이의 관계](/1-1_figure-1.svg)

클래스 기반 객체 지향 언어에서는 일반적으로 인스턴스가 상태를 보유하고 클래스가 메서드를 보유하며, 구조와 동작만 상속된다. ECMAScript에서는 객체가 상태와 메서드를 모두 보유하며, 구조와 동작뿐 아니라 상태도 상속된다.

프로토타입이 가진 특정 속성을 직접 가지고 있지 않은 모든 객체는 그 속성과 값을 공유한다. 그림 1은 이러한 관계를 보여 준다.

`CF`는 생성자이면서 객체이기도 하다. `new` 표현식을 사용하여 `cf1`, `cf2`, `cf3`, `cf4`, `cf5`라는 다섯 객체를 생성했다. 각 객체에는 `"q1"`과 `"q2"`라는 이름의 속성이 있다. 점선은 암묵적인 프로토타입 관계를 나타낸다. 예를 들어 `cf3`의 프로토타입은 `CFp`다. 생성자인 `CF` 자체에는 `"P1"`과 `"P2"`라는 두 속성이 있지만, 이 속성들은 `CFp`, `cf1`, `cf2`, `cf3`, `cf4`, `cf5`에서는 보이지 않는다. `CFp`의 `"CFP1"` 속성은 `cf1`, `cf2`, `cf3`, `cf4`, `cf5`가 공유하지만 `CF`는 공유하지 않는다. 또한 `CFp`의 암묵적인 프로토타입 체인에서 찾을 수 있는 속성 중 이름이 `"q1"`, `"q2"`, `"CFP1"`이 아닌 속성도 이 다섯 객체가 공유한다. `CF`와 `CFp` 사이에는 암묵적인 프로토타입 연결이 없다는 점에 유의해야 한다.

대부분의 클래스 기반 객체 언어와 달리 ECMAScript에서는 값을 할당하여 객체에 속성을 동적으로 추가할 수 있다. 즉 생성자는 생성된 객체의 모든 속성 또는 일부 속성의 이름을 미리 지정하거나 값을 할당할 필요가 없다. 위 그림에서는 `CFp`에 새로운 속성값을 할당하여 `cf1`, `cf2`, `cf3`, `cf4`, `cf5`가 공유하는 새로운 속성을 추가할 수 있다.

ECMAScript 객체는 본질적으로 클래스 기반은 아니지만, 생성자 함수, 프로토타입 객체 및 메서드로 이루어진 공통 패턴에 기반하여 클래스와 비슷한 추상화를 정의하면 편리할 때가 많다. ECMAScript 내장 객체 자체도 이러한 클래스 유사 패턴을 따른다. ECMAScript 2015부터는 프로그래머가 내장 객체에서 사용하는 것과 동일한 클래스 유사 추상화 패턴을 따르는 객체를 간결하게 정의할 수 있도록 클래스 정의 구문이 ECMAScript 언어에 포함되었다.

<h2 id="sec-strict-variant-of-ecmascript">
  4.3.2 ECMAScript의 엄격 변형
</h2>

<!-- 원문 제목: The Strict Variant of ECMAScript -->

<!-- 원문: https://tc39.es/ecma262/multipage/overview.html#sec-strict-variant-of-ecmascript -->

ECMAScript 언어는 일부 사용자가 언어에서 사용할 수 있는 특정 기능의 사용을 제한하고자 할 가능성을 인정한다. 사용자는 보안을 강화하거나, 오류를 일으키기 쉽다고 판단하는 기능을 피하거나, 더 강화된 오류 검사를 적용하거나, 그 밖에 자신이 선택한 이유로 이러한 제한을 적용할 수 있다. 이러한 가능성을 지원하기 위해 ECMAScript는 언어의 엄격 변형을 정의한다. 언어의 엄격 변형은 일반 ECMAScript 언어의 특정 구문적·의미론적 기능을 제외하고 일부 기능의 세부 의미론을 변경한다. 또한 비엄격 형식에서는 오류로 규정되지 않는 상황에서도 오류 예외를 던져 보고해야 하는 추가 오류 조건을 규정한다.

ECMAScript의 엄격 변형은 일반적으로 언어의 엄격 모드라고 한다. 엄격 모드의 선택과 ECMAScript 엄격 모드 구문 및 의미론의 사용 여부는 [11.2.2 엄격 모드 코드](doc:types-of-source-code#sec-strict-mode-code)에 설명된 것처럼 개별 [ECMAScript 소스 텍스트](doc:source-text#sec-source-text) 단위 수준에서 명시적으로 결정된다. 엄격 모드는 구문적인 [소스 텍스트](doc:source-text#sec-source-text) 단위 수준에서 선택되므로, 해당 [소스 텍스트](doc:source-text#sec-source-text) 단위 안에서 국소적으로 영향을 미치는 제한만 부과한다. 엄격 모드는 여러 [소스 텍스트](doc:source-text#sec-source-text) 단위에 걸쳐 일관되게 작동해야 하는 ECMAScript 의미론의 어떠한 측면도 제한하거나 변경하지 않는다. 하나의 완전한 ECMAScript 프로그램은 엄격 모드와 비엄격 모드의 [ECMAScript 소스 텍스트](doc:source-text#sec-source-text) 단위를 함께 포함할 수 있다. 이 경우 엄격 모드는 엄격 모드 [소스 텍스트](doc:source-text#sec-source-text) 단위 안에서 정의된 코드를 실제로 실행할 때만 적용된다.

ECMAScript 구현체가 이 명세를 준수하려면, 이 명세에서 정의하는 제한되지 않은 전체 ECMAScript 언어와 ECMAScript 언어의 엄격 변형을 모두 구현해야 한다. 또한 구현체는 제한되지 않은 [소스 텍스트](doc:source-text#sec-source-text) 단위와 엄격 모드 [소스 텍스트](doc:source-text#sec-source-text) 단위를 하나의 복합 프로그램으로 결합하는 것도 지원해야 한다.
